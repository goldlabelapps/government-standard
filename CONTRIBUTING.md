# Contributing

This is an independent draft standard. Contributions should make its controls clearer, more enforceable, more practical or better supported by evidence.

## Proposing a change

Open an issue or pull request and include:

- The problem or ambiguity and the people or workflows affected.
- The control identifier(s) and proposed wording, if applicable.
- Whether the change is normative or explanatory.
- Implementation and verification implications, including evidence an organisation could retain.
- Authoritative references for claims about external requirements.

Do not include sensitive, classified, personal or client information in issues or pull requests. Use public examples or synthetic data.

## Review

Changes to normative requirements should receive review for technical enforceability, proportionality, accessibility, compatibility with existing control IDs, and interaction with law, contracts and organisational policy. External frameworks should be described accurately and separately from this project's proposed controls.

Control IDs are stable and must not be reused. Material requirement changes belong in a new version and should be recorded with their rationale. The project does not provide certification or official endorsement.
